# Shared Donation Sky Design

## Goal

Turn the donation sky from a browser-local demonstration into a shared, real-time experience. When a visitor completes the existing simulated donation flow, a diamond star is recorded once and appears for every visitor currently viewing the site.

The feature remains a simulation. It does not collect, validate, or process a real payment.

## Constraints

- The public site remains hosted on GitHub Pages.
- The first release must use a no-cost service tier.
- Visitors do not need to create an account.
- Donor names remain optional; the default label is `匿名微光`.
- No payment credentials, contact details, or receipts are written to the shared database.
- The site must still show a local star when the shared service is unavailable.

## Architecture

Use a Supabase Free project as the shared data and real-time layer.

The browser loads the Supabase JavaScript client from the official CDN, reads the newest shared stars from a `donation_stars` table, then subscribes to inserted rows. The existing canvas remains the only renderer; it will draw a merged, de-duplicated view of remote and fallback-local stars.

GitHub Pages contains only the Supabase project URL and publishable anonymous key. These values are intentionally public browser configuration. Row Level Security policies, database constraints, and a narrow public schema protect the database; the service-role key is never placed in this repository or browser.

## Data Model

`public.donation_stars`

| Field | Type | Rule |
| --- | --- | --- |
| `id` | UUID | Primary key, generated by the database |
| `amount` | integer | 1 through 999999 |
| `project` | text | One of the three existing project labels |
| `anonymous_label` | text | 1 through 24 characters; defaults to `匿名微光` |
| `x` | numeric | 0.18 through 0.86 |
| `y` | numeric | 0.10 through 0.52 |
| `created_at` | timestamptz | Generated by the database |

Only the latest 80 shared rows are loaded in the initial view. The database retains stars for the first release so the sky can remain collective across sessions.

## Access Control

Row Level Security is enabled.

- Anonymous visitors can select rows.
- Anonymous visitors can insert only valid rows.
- Anonymous visitors cannot update or delete rows.
- Insert validation enforces field ranges, allowed projects, and label length.

This is appropriate for a public simulated-interaction page, but it does not provide payment verification or robust abuse prevention. If the site later accepts money, a server-side payment webhook and rate limiting become required before a star is inserted.

## Browser Behavior

1. On site load, read the most recent shared stars and begin a real-time insert subscription.
2. When a visitor confirms a simulated donation, create the star locally first so its flight animation starts without network delay.
3. Submit the same star to Supabase. When the insert event arrives, replace or merge it by ID so it is not drawn twice.
4. For stars created by other visitors, draw a short arrival pulse rather than a flight from the local donate button.
5. When the database cannot be reached, preserve the current `localStorage` fallback and show a brief non-blocking notice.

## Files and Tests

- Add a small `supabase-config.js` file with deploy-time project URL and publishable key placeholders.
- Update `index.html` to load the official Supabase client and configuration before `donation.js`.
- Refactor `donation.js` so the canvas reads a shared in-memory star collection rather than directly reading `localStorage` each frame.
- Add a SQL setup script with schema, constraints, Realtime publication, and RLS policies.
- Extend the existing Python tests to cover the fallback path, required client integration points, and the absence of sensitive service keys.

## Operational Setup

The user creates a free Supabase project through the browser and grants this task access to configure the table. The browser setup is the only required account action. After configuration, the project URL and publishable anonymous key are committed to the public site, then the existing GitHub Pages deployment is updated.

Free Supabase projects can pause after one week without sufficient activity. The site will continue to render its static sky while the project is paused; the owner can resume it from the Supabase dashboard.
